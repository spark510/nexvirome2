# Bug exploration — 2026-09-07

Status: **all five reproduced defects fixed**. Scope was SAM confidence/anchor
accounting, frozen production settings, and mixed-feature NMF edge cases. This is
not an exhaustive repository review. The descriptions below preserve the original
reproductions; line numbers refer to the pre-fix source.

## Fix verification

- All CLI subparsers inherit exact long-option parsing. Production recipes accept
  only canonical per-command data arguments and reject embedded option tokens.
  Effective saved settings are checked against the frozen implementation.
- Anchor support is summed from M/=/X aligned blocks. D/N and soft clipping cannot
  contribute bases. A qualifying 20-base anchor still supports the positive control.
- MAPQ 255 is excluded from unique coverage. Explicit secondary placements are
  compared per mate: equal/better scores or unavailable comparison scores exclude
  the fragment. Strictly lower-scoring alternatives remain eligible when primary
  MAPQ and other checks pass. Supplementary alignments remain conservative exclusions.
- NMF fits only informative entities and preserves all-zero entities as `inactive`
  rows with zero loadings. Their coordinates remain present; no transition is
  inferred across an inactive window. Model NPZ stores the active-row mask.

## P1 — Frozen configuration bypass through argparse abbreviations

`production.py:73` rejects exact reserved argument names but forwards other keys to
argparse, which accepts long-option abbreviations. A recipe key `conf` overrides
the earlier `--config` path while passing the reserved-name check. A policy frozen
with `mode: hard` successfully executed `mask export` using `mode: unmasked`, and
the outer manifest reported `complete`. The implementation hash still matched
the original frozen configuration, not the effective replacement configuration.

Suggested repair: disallow option abbreviation for every parser/subparser and
validate recipe keys against canonical per-command data-input arguments. Confirm
that recorded effective settings match the frozen implementation. This is a local
configuration-integrity defect, not a claim of remote exploitability.

## P1 — Deleted reference bases can satisfy the 20-base anchor criterion

`correction/support.py:43` checks position and reference-span endpoints rather than
actual aligned blocks. A `10M20D140M` alignment starting at zero-based position 75
has only 10 aligned bases before upstream boundary 100, yet passes the 20-base
anchor requirement. Three distinct such fragment endpoints produced alternative
support 3 and `decision(0,3) == split`.

Suggested repair: measure actual M/=/X overlap with each required anchor; do not
count D/N, clipped bases or unsequenced fragment gaps as read support. Preserve
the independent-fragment and competing-path checks. The reproduction tests the
support counter and decision function, not a naturally occurring misassembly.

## P2 — MAPQ 255 is accepted as high confidence

`io/sam.py:49` treats 255 as greater than the minimum MAPQ. A pair with both MAPQs
255 was counted as one accepted fragment, 100 aligned bases and depth 0.2 over a
500-base interval. The [SAM specification](https://samtools.github.io/hts-specs/SAMv1.pdf)
defines 255 as unavailable mapping quality, not maximal confidence.

Suggested repair: explicitly exclude unavailable MAPQ from the unique-coverage
path, unless a separately validated policy supplies adequate alternative evidence.
This affects imported SAM; it is not a claim that default Bowtie2 emits MAPQ 255.

## P2 — Explicit equal-score secondary alignments are ignored

`io/sam.py:47–55` discards secondary records before checking ambiguity, consulting
only primary AS/XS tags. A pair aligned to two reference records with equal AS,
secondary flags on the alternative and no XS was still accepted as unique coverage.
The optional XS tag need not exist in an imported SAM.

Suggested repair: compare the available competing paired alignments as well as
primary tags; unknown competition must not silently become unique support.
The fixture deliberately supplies high primary MAPQ alongside equal-score
alternatives to verify how contradictory imported evidence is handled.

## P2 — All-zero observed feature rows break the next NMF stage

`multiview.py:167` writes all-zero normalized loadings for an entity with all-zero
measured features. Such a row is valid under the input contract and passes fitting.
In the fixture the fit finished with `proposal_eligible: true`, but
`multiview.py:30` rejected those same loadings with `Invalid normalized loadings`.

Suggested repair: identify inactive entities, retain explicit unresolved status
and coordinates, and exclude them from inference/proposal transitions without
bridging over the inactive windows. Do not turn zero features into imputed
positive component membership.

Five current-failure assertions passed in the standalone reproducer. That means
the defects were demonstrated, not that corrected behavior passed regression tests.

## Follow-up SAM audit: repaired

- Reject zero, negative and non-finite `score_margin` before starting correction
  or reading SAM. Equal-score paths remain ambiguous and cannot trigger a split.
- When an `XS` competitor exists, coverage requires finite, parseable primary and
  competitor scores with a strictly better primary. Missing/invalid scores are
  excluded; MAPQ alone cannot override this uncertainty.
- A QC-failed or duplicate-marked alignment excludes the entire fragment from
  correction support, including other placements. Exclusions appear in the audit.
- Correction now groups arbitrary-order SAM records in a temporary SQLite database
  and streams fragment audit JSON. Interleaved mates and alternatives remain grouped;
  endpoint deduplication is preserved. Audit fragments are emitted in name order.
  This trades temporary disk I/O for lower alignment/audit memory usage. Unique
  supporting endpoint sets and one fragment's competing hits still consume RAM;
  this is not a claim of constant memory or a measured large-data speedup.

Regression coverage is in `tests/test_pair_evidence_validation.py`.
